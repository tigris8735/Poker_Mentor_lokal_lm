# Системный анализ

## 1. Функциональные требования

### 1.1. Управление пользователями
- **Регистрация и идентификация** через Telegram ID
- **Создание профиля** автоматически при первом использовании
- **Отслеживание статистики** игр и прогресса обучения

### 1.2. Игровая система
- **🎯 Начало новой игры** (`/game`)
  - Инициализация покерного стола
  - Раздача карт (2 карты игроку, 2 карты AI)
  - Установка блайндов (10/20)

- **🃏 Игровые действия**
  - **Fold** (`/fold`) - сброс карт
  - **Call** (`/call`) - уравнивание ставки  
  - **Raise** (`/raise`) - повышение ставки
  - **Check** (`/check`) - пропуск хода (если возможно)

- **📊 Управление игрой**
  - Последовательная смена улиц: Preflop → Flop → Turn → River
  - Автоматические действия AI-оппонента
  - Определение победителя на шоудауне

### 1.3. AI-аналитика
- **Анализ раздач** (`/analyze`)
  - Прием описания игровой ситуации от пользователя
  - Генерация профессионального анализа с рекомендациями
  - Учет позиции, размера банка, действий оппонентов

- **Контекстные советы** (`/advice`) 
  - Ответы на конкретные стратегические вопросы
  - Объяснение покерных концепций
  - Персонализированные рекомендации

### 1.4. Система обучения
- **Объяснение концепций** (`/concept`)
  - Теория покера в доступной форме
  - Примеры применения концепций
  - Связь с практическими ситуациями

## 2. Нефункциональные требования

### 2.1. Производительность
- **Время отклика**: <2 секунды для большинства команд
- **AI-анализ**: <10 секунд при использовании локальной модели
- **Одновременные пользователи**: поддержка 50+ активных сессий

### 2.2. Безопасность
- **Аутентификация**: через защищенный Telegram API
- **Данные пользователей**: локальное хранение в зашифрованной БД
- **Отсутствие реальных денег**: тренировочная система с виртуальными фишками

### 2.3. Надежность
- **Доступность**: 95% uptime (исключая плановые обновления)
- **Оффлайн-работа**: базовая функциональность при недоступности AI
- **Восстановление после сбоев**: автоматический перезапуск игровых сессий

### 2.4. Совместимость
- **Платформа**: любой устройство с Telegram
- **Версия Python**: 3.8 и выше
- **База данных**: SQLite с возможностью миграции на PostgreSQL

## 3. Технологический стек

### 3.1. Backend
- **Язык**: Python 3.8+
- **Фреймворк бота**: Aiogram 3.x
- **Асинхронность**: asyncio, aiohttp

### 3.2. База данных
- **Основная**: SQLite с SQLAlchemy ORM
- **Модели**: User, HandHistory, GameSession
- **Миграции**: Alembic (готовность к использованию)

### 3.3. Искусственный интеллект
- **Локальный AI**: LM Studio с моделью Qwen
- **API**: RESTful совместимость с OpenAI API
- **Оффлайн-режим**: система заглушек с базовыми советами

### 3.4. Инфраструктура
- **Конфигурация**: environment variables + .env файлы
- **Логирование**: structured logging с ротацией
- **Развертывание**: Docker-контейнеризация (готовность)

## 4. Ограничения системы

### 4.1. Технические ограничения
- Требует локальной установки LM Studio для полной функциональности AI
- Ограничения Telegram Bot API (30 сообщений/секунду на чат)
- Размер контекста AI-модели (зависит от конкретной модели Qwen)

### 4.2. Функциональные ограничения
- Только Texas Hold'em формат
- Один AI-оппонент (без мультиплеера)
- Базовые стратегии AI (не профессиональный уровень)
